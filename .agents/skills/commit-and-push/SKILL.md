# 修改后的 Git 交付

用户已要求本项目修改完成后默认提交并推送。完成当前请求的实现和适当验证后执行，不必重复询问是否提交或推送；用户当前明确要求暂不提交或暂不推送时遵循该要求。这项约定不授权提交其他任务的改动、强推、部署或发布。

## 提交范围

- 从当前仓库根目录检查分支、上游、远端、工作区和暂存区。记录开始时已有的改动，避免把其他聊天或用户的工作一起提交。
- 只暂存本任务文件和必要的 Unity `.meta`。同文件混有其他任务修改时按差异块暂存；保留其他修改及原有暂存状态。不要使用无范围的 `git add .` 或 `git add -A`。
- 不提交 `.uloop/`、`UserSettings/`、IDE 本地文件、凭据或生成缓存。不要为了清理工作区而回退其他修改。

## 验证和提交

- 按改动类型完成必要验证；C#、预制体及运行行为遵循项目对应的 uloop 技能。已有有效验证无需重复执行。编译工具断连不能当作编译成功；确认恢复后的实际编译和运行状态。
- 检查 `git diff --cached --check` 和暂存差异，确认提交范围、资源依赖与说明一致。提交信息简要说明最终改动及目的。
- 本任务造成的验证失败先修复。遇到明确无关的既有阻塞时保留证据，提交说明和最终回复注明未通过的检查，不宣称完整验证通过。

## 推送与确认

- 使用当前分支已有的上游推送。没有上游时核实当前远端和分支；新建分支遵循项目 `codex/` 前缀。仅在目标无法确定时询问。
- 本项目 Git 代码在 GitHub、LFS 对象在 NAS Gitea；不要改变 origin 来处理 LFS 问题。涉及 LFS 上传或故障时读取 [project-lfs](../project-lfs/SKILL.md)，保留正常 pre-push hook，不跳过 LFS 检查。
- 正常执行 `git push`。遇到远端领先，先 fetch 并检查差异，在能保护未提交工作的情况下整合远端；不要强推或盲目覆盖。认证、网络或服务问题在定位后做有依据的重试，无法解决则停止并报告，保留本地提交。
- 成功后核对远端分支 SHA 与本地提交一致。最终回复给出提交短 SHA、推送目标、验证结果及剩余阻塞；提交成功但推送失败须明确区分。
